# RICHMOND SUNLIGHT MACHINE CRONTAB
#
# Update tasks are no longer scheduled here. They live in cron/tasks.php, and the single heartbeat
# line below asks the runner once a minute what is due. This exists because the schedule used to be
# maintained in two places — this file, and the chain of `if ($type == 'all' || ...)` statements in
# cron/update.php — with nothing keeping them in agreement. Seven task types drifted into being
# both inside the "all" pass and separately scheduled here, so they could run twice at once.
#
# To change when something runs, edit cron/tasks.php, not this file. That file is covered by
# deploy/tests/TaskManifestTest.php, which fails the build if a task is both scheduled and in the
# "all" pass, if a task's timeout exceeds its own interval, or if a cron expression does not parse.
#
# Useful commands:
#   php cron/run.php --list      What tasks exist, when they run, and their timeouts.
#   php cron/run.php --crontab   The per-task crontab lines this heartbeat replaces (reference).
#   php cron/run.php --due       What is due this minute (what the heartbeat itself runs).
#   php cron/run.php summaries   Run one task by hand.
#   php cron/run.php all         Run the whole combined pass by hand.
#
# The runner takes a per-task lock keyed on the task name, so a task cannot overlap itself no
# matter how it was invoked. The outer flock here is a second layer: it stops the heartbeat process
# itself from stacking up if one tick is somehow still going a minute later. `-n -E 0` means a
# contended lock exits 0 quietly, so cron sends no mail.

# ---- The heartbeat -----------------------------------------------------------------------------
# Runs whatever cron/tasks.php says is due this minute, including the combined "all" pass. Most
# minutes nothing is due and this exits immediately.
* * * * * /usr/bin/flock -n -E 0 /run/lock/rs-tick.lock /usr/bin/php rs-machine/cron/run.php --due

# ---- Standalone PHP scripts --------------------------------------------------------------------
# These are not update.php task types: each is its own entry point with its own includes and
# database setup, so the runner does not manage them. They keep their own locks and schedules.

20,21,22,23,24,25 * * 1-3,10-12 * /usr/bin/flock -n -E 0 /run/lock/rs-update_places.lock /usr/bin/php rs-machine/cron/update_places.php

#36 03,15 * * * /usr/bin/php rs-machine/cron/mirror.php

# ---- Shell and third-party tooling -------------------------------------------------------------
# Not PHP, so outside the runner's scope entirely.

# Nightly DB backup (keep last 3).
00 04 * * * /bin/bash rs-machine/deploy/db_backup.sh

# Re-zip the current year's downloadable bill full-text HTML. The year is substituted at run time,
# so this does not need updating annually. Note that `%` must be escaped as `\%` in a crontab.
0 3 * * * /usr/bin/zip -rj rs-machine/downloads/bills/$(date +\%Y) rs-machine/downloads/bills/$(date +\%Y)

# Convert bill data to JSON.
0 * * * * csvtojson --ignoreEmpty=true rs-machine/cron/bills.csv > rs-machine/downloads/bills.json

# Store exports on S3.
5 * * * * /usr/bin/flock -n -E 0 /run/lock/rs-s3-sync.lock aws s3 sync rs-machine/downloads s3://downloads.richmondsunlight.com --grants read=uri=http://acs.amazonaws.com/groups/global/AllUsers --storage-class REDUCED_REDUNDANCY >/dev/null 2>&1

# Store mirrored sites on S3.
30 3 * * sun rs-machine/cron/mirror_to_s3.sh >/dev/null 2>&1

# ---- Notes on what changed ---------------------------------------------------------------------
#
# CSV fetches are gone from this file. Each was a separate line scheduled a minute before whichever
# task consumed it, with the pairing implied only by adjacency. They are now declared on the task
# itself via `prefetch` in cron/tasks.php, and the runner fetches them immediately after taking the
# task's lock — so the download cannot race a concurrent run of the same task.
#
# The overlap problem is solved rather than documented: tasks that were both in "all" and scheduled
# individually (summaries, full_text, code_sections, download_pdfs, dockets, meetings,
# fiscal_impact) are now `in_all => false`, and a test fails the build if that regresses. Even if it
# did, the runner's per-task lock is keyed on the task name, so "all" doing summaries and a
# scheduled summaries run would contend for the same lock instead of running concurrently.
#
# Timeouts are per task rather than one global 20-minute ceiling. That ceiling used to exceed some
# tasks' own intervals — `history` runs every 10 minutes — so a slow run silently ate later ticks.
# TaskManifestTest asserts each timeout fits inside its task's interval.
